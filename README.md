# 广工赛机器人车：STM32 底盘与 MaixCAM2 视觉协同

本工程使用 **R550 C30D 2.0 Mini 麦克纳姆轮底盘**，底盘控制器为 **STM32F407**，通过四轮 GMR 编码器与板载 IMU 估计位姿；视觉端使用 **MaixCAM2**，运行 MaixPy 程序识别二维码、彩球和靶标。两个控制器通过 3.3 V TTL UART 通信，完成识别、停车、对中和任务切换。机械臂、夹爪与激光执行机构由底盘固件按任务状态驱动。

## 整车技术实现

```text
四轮编码器 ─┐
           ├─ STM32F407 底盘 ─ 电机速度控制 ─ 麦轮底盘
板载 IMU ──┘         │
                     ├─ 路线与任务状态机 ─ 机械臂／夹爪／激光
                     │
MaixCAM2 UART4 ── 底盘 UART5 ──┘
  ├─ 二维码解析
  ├─ 彩球识别与坐标发送
  └─ 靶标识别与停车事件
```

底盘的 `chassis_odom.c` 每个控制周期结合四轮编码器和 IMU 更新平面位姿。`chassis_auto_route.c` 根据路线点、车体位姿和任务阶段输出麦轮三轴速度，并负责横向偏差修正、停车、等待视觉事件及终点失能。MaixCAM2 的 `main.py` 调度视觉任务；`tasks/` 执行识别，`common/` 提供颜色、ROI、目标排序、串口等工具。视觉端在检测到任务事件后发送单字节指令或带 CRC 的目标坐标包，底盘通过 `vision_uart.c` 解析。

当前主流程为：**起点 → 第一路口扫码 → 第五拐口搜球与对中 → 机械臂抓取和放球 → 寻找靶标并打靶 → 外侧拐角 → 返回终点**。代码保留了部分早期救援任务分支以便追溯，但当前路线在打靶后跳过该任务。路线坐标、靶位标定值、机械臂角度和视觉阈值均与实车安装和赛场条件有关，不能直接当作通用参数使用。

## 硬件与通信

| 项目 | 当前工程配置 |
| --- | --- |
| 底盘 | R550 C30D 2.0 Mini，麦克纳姆轮，四轮 GMR 编码器 |
| 主控 | STM32F407，Keil MDK 工程 |
| 视觉 | MaixCAM2，MaixPy |
| 视觉串口 | 相机 UART4：A21/TX、A22/RX；底盘 UART5：PD2/RX、PC12/TX；双方共地 |
| 串口参数 | 115200 bps、8N1、3.3 V TTL |
| 姿态与运动 | 板载 IMU、轮速反馈、麦轮速度控制 |

相机 TX 接底盘 RX，相机 RX 接底盘 TX。二维码成功事件、彩球检测与靶标事件，以及目标坐标包的字段和时序，见 `vision/PROTOCOL.md`、`vision/BALL_CHAIN_NOTES.md` 与底盘 `R550_C30D(2.0)_Mini小车STM32源码_GMR编码器_2025.12.26/HARDWARE/vision_uart.c`。协议文档中保留了历史版本描述，联调时应以当前双方源码为准。

## 构建、部署与验证

1. 使用 Keil MDK 打开 `R550_C30D(2.0)_Mini小车STM32源码_GMR编码器_2025.12.26/USER/WHEELTEC.uvprojx`，按 STM32F407 项目设置编译和烧录底盘。
2. 将 `vision/` 中的 MaixPy 程序及配置文件部署到 MaixCAM2；确认 UART4 引脚映射与底盘 UART5 接线。
3. 架空车轮，先检查电机方向、编码器符号、IMU 数据、使能与急停，再确认视觉事件收发。
4. 在场地上从低速短路线开始，标定轮速比例、路线坐标、视觉阈值和执行机构位置。

相机包构造的 CRC 逻辑已集中到 `vision/main.py` 中的 `crc8_payload()`；`tests/test_packets.py` 用固定协议帧验证重构前后的输出一致。本次整理未对底盘控制逻辑做额外重构；底盘文件更新来自当前实车工程。**源码与静态测试通过不等于实车全流程验证完成。**
