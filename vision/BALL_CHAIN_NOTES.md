# 抓球完整链路（2026-11-05 V2）

使用本目录完整视觉工程。main.py启动标记为 `[BUILD] BALL_CHAIN_20261105_V2`。底盘需烧录同次生成的WHEELTEC.hex。

## 编号不要混用

官方二维码/视觉检测内部：1红、2绿、3蓝。线上颜色字段按用户要求：1红、2蓝、3绿，转换函数为main.py的chassis_ball_color。
发现目标色球立即发0x51/0x52/0x53（停车事件+颜色），随后发送原15字节AA55坐标包，color字段同样使用1红2蓝3绿。不是直接发送单字节1/2/3，因为旧协议中这些字节是任务心跳。

球的摆放顺序抽签，因此颜色不能决定球位。底盘Route_BallColor保存颜色，Route_BallSlot保存物理球位（沿行进方向1、2、3）。

## 初始参考坐标（米）

当前路线X=FIELD_X(2.560)=2.460，桶前Y=0.855。官方示意图三个球中心总跨度300mm，估计间距150mm，以中球与桶对齐作为初始假设。

|行进顺序球位|参考X|参考Y|颜色|
|---|---|---|---|
|1，下方、先经过|2.460|1.005|抽签|
|2，中间|2.460|0.855|抽签|
|3，上方、后经过|2.460|0.705|抽签|

这是底盘在球前的参考位置，不是球本体世界坐标，也不是相机像素坐标。实际镜头偏置和机械臂伸出姿态会影响底盘居中位置，必须实测标定。
chassis_auto_route.c中的ball_slot_offset_y为相对桶前Y的偏移[0.150,0,-0.150]，IdentifyBallSlot按居中后的轮式里程计Y选择最近位置，差值超过0.070m就停车，不自动猜测球位。里程计漂移可能误判球位，本实现没有外部绝对定位。不会用参考坐标覆盖里程计。
Route_BallReferenceX/Y为参考坐标，Route_BallMeasuredX/Y为居中时估计坐标。

## 顺序

第五角伸臂 -> 0.05m/s搜索 -> 发现指定颜色停车 -> XY视觉居中 -> 识别物理球位 -> APPROACH前伸 -> PICK闭爪 -> CARRY收回保持夹紧 -> 先回路线X再到桶前Y（均低速） -> BUCKET转臂/投放姿态 -> 等2秒 -> RELEASE松爪 -> 等1秒 -> BUCKET_FINISH收臂 -> 继续原路线。

没有抓取反馈传感器，PICK等待结束只代表指令时序完成，不保证实物已经抓牢。

## 用户调整机械臂角度

全部在HARDWARE/arm_task.c的ArmMission_Apply函数中直接修改Arm_SetAngle调用，不用宏。
- EXTEND：保留用户当前0号90、1号0。
- APPROACH：0号105、1号-50；需标定。
- PICK：抓爪2号-80；需标定。
- CARRY：0号90、1号0，抓爪保持闭合。
- BUCKET：0号-80、1号90；3号按球位1/2/3分别75/85/95。这三值只是独立可调示例，非机械计算角度。
- RELEASE：抓爪2号-100，转臂等待完成后才执行。
- BUCKET_FINISH：0号0、1号0、3号85，抓爪保持打开。

如果车到同一桶前且最终车身位姿一致，三个球位往往应使用相同投放角度。三个分支是为用户实测标定保留，不代表颜色本身要求不同投放方向。
